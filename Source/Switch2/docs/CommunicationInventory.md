# Milestone 3 memory and communication syscall inventory

Numbers are Linux x86-64 ABI numbers. A routed syscall has a Switch 2
dispatcher handler: a `case` in the `switch (Registers[REG_RAX])` block of
`GuestSyscalls::HandleSyscall` in `GuestRuntime.cpp`. `Partial` means
routed with known gaps named in Notes. `Unrouted` returns ENOSYS. Semantics
and console acceptance are tracked in [NextMilestone.md](../NextMilestone.md).
Format follows [ProcessInventory.md](ProcessInventory.md). Work packages
2-5 add their rows to the pipe/IPC and socket groups; WP1 owns the virtual
memory group.

## Console verification

Passed on launcher 0.14.2 (2026-11-24), Debian rootfs, console on Wi-Fi:
`/bin/comm-acceptance.elf` printed `Communication acceptance results:
suite 42, tools 42` (comm-suite 124 passed, 0 failed, 1 skipped; tools
including `xz_threads_roundtrip`, `sort --parallel`, `nc` over Unix, UDP
and TCP, `getent`); `/bin/comm-suite-root.elf` 124/0/1, exit 42. The
same run passed `/bin/filesystem-acceptance.elf` (`ABI 42, coreutils 0,
suite 42`); 0.14.1 passed `/bin/process-acceptance.elf` (`suite 42,
tools 42`) and an interactive `nc -l 0.0.0.0` reached from a LAN PC. The
launcher shrinks the loader heap to 2 GiB at start (`Heap: ... 9090 MiB ->
2049 MiB`), giving the arena a 6144 MiB commit limit. Console fixes found
on the way are in `.superpowers/sdd/m3-console1-report.md` (local).

## Deliberate differences

| Interface | Behavior |
| --- | --- |
| No SIGSEGV for guest `PROT_NONE` or unmapped access | A CPU fault ends the app (m3probe 5: user exception handlers never run). Syscalls check the runtime's page table and return EFAULT; a guest load or store to a guest-`PROT_NONE` or unmapped page cannot raise SIGSEGV. Known gap: GC write barriers, JVM implicit null checks, guard-page stack probing. Host pages are never set to `Perm_None` or `Perm_R` |
| Self-modifying code | `InvalidateExecutableRange` runs on mmap, mprotect, munmap, mremap, and on runtime stores into guest memory (`read`, `pread`, `readv`, `recv*`, `process_vm_*`). Direct guest stores into RWX pages are not detected: FEX's default `SMCChecks=mtrack` needs write faults. Programs that rewrite executable pages without calling mprotect (JITs) need `SMCChecks=full` |
| AF_UNIX stream capacity | A stream socket queues 64 KiB regardless of SO_SNDBUF and SO_RCVBUF (Linux accounts skb memory: about 93 thousand-byte sends). The buffer options are stored and reported but only change datagram and seqpacket accounting |
| AF_UNIX out-of-band data | MSG_OOB on send is EOPNOTSUPP and on stream receive EINVAL (Linux 7.3 supports it with CONFIG_AF_UNIX_OOB) |
| `SO_PASSPIDFD` and `SCM_PIDFD` | ENOPROTOOPT, as on Linux before 6.5 (no pidfd control messages). Programs that ask for it fall back to SO_PEERCRED/SCM_CREDENTIALS |
| AF_UNIX garbage collection | A socket whose own descriptor (or a cycle A holds B holds A) sits in a queued SCM_RIGHTS message is never freed (Linux runs the unix garbage collector): the sockets and their bound names live until the launcher exits |
| Vectored stream `sendmsg` | A stream send with more than one iovec copies the whole iov total at once (up to MAX_RW_COUNT); a very large one returns ENOMEM where Linux sends progressively |
| AF_UNIX families | AF_INET6, AF_NETLINK and AF_PACKET `socket()`: EAFNOSUPPORT (the host service rejects IPv6; there is no netlink) |
| AF_INET INADDR_ANY | Not a difference: Horizon allows binding 0.0.0.0 (console-verified 2026-11-24, `BindProbe.cpp`), so a wildcard `bind` and the implicit bind of `listen` and of a datagram `sendto` pass INADDR_ANY to the host. `connect`/`sendto` to 0.0.0.0 means loopback, as on Linux. |
| AF_INET families and types | No AF_INET6, AF_NETLINK or AF_PACKET (EAFNOSUPPORT). `SOCK_RAW` needs CAP_NET_RAW (EPERM) and only IPPROTO_ICMP (else EPROTONOSUPPORT); datagram ICMP sockets (ping sockets): EPROTONOSUPPORT; SOCK_SEQPACKET and unknown types: ESOCKTNOSUPPORT |
| AF_INET socket limit | The host service gives 126 sockets per process; the call that would pass it returns ENFILE (-23), not EMFILE |
| AF_INET options | `TCP_INFO` returns 232 zero bytes with only `tcpi_state`. `SIOCOUTQ` is 0. `SO_BINDTODEVICE` accepts only an empty name (else ENODEV). `SO_TIMESTAMP`, `SO_SNDLOWAT`, `TCP_CORK`, `TCP_QUICKACK`, `TCP_DEFER_ACCEPT`, `TCP_USER_TIMEOUT`, `TCP_NOTSENT_LOWAT`, `TCP_FASTOPEN`, `TCP_SYNCNT`, `TCP_LINGER2`, `TCP_WINDOW_CLAMP`, `IP_RECVERR`, `IP_MTU_DISCOVER`, `SO_INCOMING_CPU` and `SO_BUSY_POLL` are stored and read back with Linux's validation but change nothing; `TCP_CONGESTION` stores "cubic" or "reno" (else ENOENT). `SO_SNDBUF`/`SO_RCVBUF` are advice to the host. Other names: ENOPROTOOPT; `IP_OPTIONS`: ENOPROTOOPT |
| AF_INET control messages | Linux accepts SCM_RIGHTS, SCM_CREDENTIALS and IP cmsgs on TCP and UDP `sendmsg` and sends none of them (verified natively; the plan said EINVAL). They are validated as `scm_send` does (EBADF for a bad descriptor, EPERM for foreign credentials) and dropped. `IP_TTL`/`IP_TOS` cmsgs are not applied. No control data is returned on receive (no `IP_PKTINFO`, `SO_TIMESTAMP` cmsg) |
| AF_INET datagram details | A `sendto` with an address on a connected UDP socket is EISCONN unless it names the peer (the host refuses it; Linux sends to the new address). The `AF_UNSPEC` disconnect relies on the host accepting a connect of family 0 (not run on the console). A datagram is limited to 65507 bytes (EMSGSIZE; the host's own UDP buffer is smaller, m3probe: 60000 failed). `MSG_MORE` and `MSG_CONFIRM` are accepted and ignored |
| AF_INET wait bits | A non-blocking `poll`/`select`/`epoll` query also records the bits it found not ready as wanted, so the scheduler's host poll may end waits for events nobody blocks on (extra scheduler passes, not wrong results) |
| AF_INET edge-triggered epoll | Readiness is sampled with the host `poll`: an edge-triggered descriptor reports on transitions of POLLIN/POLLOUT/POLLHUP between samples, not on every arrival while it stays readable |
| AF_INET unconnected stream shutdown | `shutdown` on an unconnected TCP socket is ENOTCONN and does not set the receive-shutdown state that Linux keeps (a later `recv` is ENOTCONN, not 0) |
| `sendfile` and `splice` with an AF_INET socket | EINVAL (not implemented) |
| SO_RCVLOWAT | Honored by blocking stream reads only. Readiness ignores it, which is also what Linux 7.3 does for AF_UNIX |
| SO_SNDBUF and SO_RCVBUF ceiling | 212992, the Linux default `net.core.wmem_max` and `rmem_max`. This host's kernel uses larger values |
| Unix datagram truesize | The per-record memory charge is modeled as the kmalloc bucket of the data plus 320 bytes plus 256 bytes (exact for records up to 8 KiB, rounded to pages above). Records are not split into paged fragments |
| SCM_CREDENTIALS and MSG_PEEK with SO_PEEK_OFF | A peek with a positive peek offset carries no rights or credential run boundary on streams |
| Datagram `MSG_EOR` | Recorded with the record and accepted on send; never reported in `msg_flags` (Linux 7.3 does not either) |
| `MAP_32BIT` | ENOMEM. Arena addresses are above 4 GiB |
| `MAP_GROWSDOWN` | Accepted; the mapping never grows downward |
| `MAP_FIXED` / `MAP_FIXED_NOREPLACE` placement | Honored over owned memory and free arena address space. Other fixed addresses (for example a non-PIE executable at `0x400000`: `svcMapPhysicalMemory` rejects addresses outside the alias region) return ENOMEM. Replacing part of a mapping with the other sharing kind (private over shared or the reverse) returns ENOMEM |
| Commit at map time | Linux commits lazily. Every accessible mapping is committed when it is created or made accessible, so overcommit is not possible: a mapping beyond the commit limit (free memory minus 1 GiB, at most 6 GiB) returns ENOMEM. Reserve-only (`PROT_NONE`) mappings may use the whole arena |
| Double shared mapping | The SDK cannot map one physical page at two addresses. Mapping a memfd or anonymous shared object twice in one process returns ENOMEM when the ranges overlap. Shared SD file views allow one view per file range in a process (ENOMEM otherwise) |
| Shared SD file coherence | A writable `MAP_SHARED` view of an SD file is compared with a clean snapshot and written back on `msync`, `munmap`, `fsync`/`fdatasync`/`syncfs`, `read`/`write`/`pread`/`pwrite` of the same inode, process exit and exec. Two views in different processes see each other's stores only at those points |
| Non-moving shared `mremap` | Anonymous shared, memfd and SD file mappings shrink in place and grow in place only when the address space after them is free; a move returns ENOMEM |
| `userfaultfd` | ENOSYS: needs fault delivery |
| `cachestat` | ENOSYS: rarely used |
| `remap_file_pages` | ENOSYS: deprecated |
| `mlock` family | Accounting only: every page is resident. `RLIMIT_MEMLOCK`, EPERM and ENOMEM are enforced; nothing is pinned |
| NUMA policy | One node. `mbind` validates but stores nothing per range; `set_mempolicy_home_node` accepts home node 0 without requiring a BIND range |
| `madvise` | DONTNEED and FREE zero accessible private pages in place (they cannot fault back in), so memory is returned to the arena only for inaccessible pages. An unmapped page in the range returns ENOMEM before any advice is applied. Tracked gap: a private file mapping is not marked file-backed, so DONTNEED zeroes it (Linux refills it from the file on the next access) and FREE zeroes it (Linux: EINVAL, FREE is for anonymous memory only) |
| `RLIMIT_DATA` | Enforced for `brk` growth only (the old break is returned); `mmap` ignores it |
| `brk` area | The heap reserves 1 GiB of address space at the first `brk`; pages above the break are unmapped (as on Linux), but the space stays reserved: other mappings land there only with MAP_FIXED, and a shared MAP_FIXED there returns ENOMEM. Pages below the break cannot be unmapped, remapped or replaced (EINVAL) |
| `munmap` of image pages | Registered ELF and stack pages cannot be given back: a range that includes them returns EINVAL (holes are skipped as on Linux) |
| Futex priority inheritance | PI futexes have no priority boosting: one host thread runs every guest thread cooperatively. PI waiters are queued FIFO and UNLOCK_PI hands the lock to the oldest waiter |
| Futex keys of vfork children | A private futex key is (address, pid): a `CLONE_VM\|CLONE_VFORK` child has its own pid, so it does not share private futex waits or wakes with its parent on the same word (Linux keys by mm). Only matters when a vfork child waits on or wakes a futex its parent uses |
| Futex ownership of a dead thread | A PI or robust futex whose owner exits without a robust list is never recovered (Linux does the same); `LOCK_PI` on a word whose owner TID is not a live thread returns ESRCH |
| Fork and returned memory | While a fork relative maps the same address space, pages are cleared from the table but stay committed in the arena until the last relative lets go |
| SysV shm commit | `shmget` commits the whole rounded segment at once (one arena block); Linux backs shm lazily, so a large sparse segment returns ENOMEM here or uses its whole size in RAM |
| SysV shm address | A segment has one address, its arena block. `shmat` with a different address returns EINVAL, a second `shmat` of a segment in the same process returns ENOMEM, and `SHM_REMAP` cannot replace a mapping. Programs that attach one segment twice or choose the address fail |
| IPC objects are not persistent | SysV objects and POSIX queues live in the launcher and vanish when it exits (as after a reboot). Waiters wake in thread-table order, not strict FIFO (Linux `update_queue`): on a contended semaphore or queue a waiter in a low thread slot can be served first repeatedly |
| No `/dev/mqueue` | The mqueue filesystem is not mounted: queues cannot be listed, `stat`ed or unlinked by path. `mq_notify(SIGEV_THREAD)`: EINVAL |
| `/dev/shm` | A flat tmpfs directory (mode 01777 root:root; one level of regular files, no subdirectories, symlinks or device nodes: `mkdir`, `symlink` and `mknod` there return EACCES). Supports `open` with O_CREAT, O_EXCL, O_TRUNC, `unlink`, `rename` (including RENAME_EXCHANGE and NOREPLACE), `link`, `truncate`/`ftruncate`, `stat`, `chmod`, `chown`, `utimensat`, `getdents64` and `mmap` MAP_SHARED through the memfd paths, so one file has one mapping per process and MAP_FIXED is rejected. Contents are lost when the launcher exits. `F_ADD_SEALS` is EPERM as on plain tmpfs; `O_TMPFILE` in the directory is EOPNOTSUPP. `rmdir` of a file there is ENOTDIR. Tracked gap: `execve` of a `/dev/shm` file returns ENOENT |
| memfd and shared pages | A memfd or `/dev/shm` file reserves arena address space for its size (a power of two, at least 4 MiB, at most 1 GiB). Growing past it extends the reservation in place, or moves the file when nothing maps it; while a mapping or pipe holds the storage and the space after it is taken, growth (`write`, `ftruncate`, `fallocate`) returns ENOMEM. Pages a mapping or pipe still references stay committed (zeroed) after a punch or truncate; whole granules return when the last reference goes |

Descriptor behavior shared by the socket calls:

| Interface | Behavior |
| --- | --- |
| `read`, `write`, `readv`, `writev` on a datagram or seqpacket socket | One record per call, as `recv` and `send` without flags |
| `ioctl(FIONREAD)` | Bytes queued on a stream; the size of the next record on a datagram or seqpacket socket. AF_INET: the host's FIONREAD (a listener EINVAL); `SIOCOUTQ` (0x5411) is 0 |
| `poll`, `epoll` | Datagram and seqpacket: POLLIN with a queued record or after SHUT_RD, POLLOUT while `(wmem << 2) <= sndbuf` (Linux `unix_writable`: gone after 70 one-byte sends, EAGAIN only at 278) and the connected peer queue is not full (more than 512 records), POLLHUP when both directions are shut. Unconnected stream and seqpacket: POLLOUT and POLLHUP. Stream and seqpacket: POLLHUP once the peer is gone, POLLERR with a pending ECONNRESET, POLLRDHUP on peer write shutdown. SO_RCVLOWAT does not change readiness (as measured on Linux 7.3) |
| `fstat` | `S_IFSOCK` with mode 0777 |
| AF_INET readiness | `poll`, `select` and `epoll` ask the host with a `poll` of timeout 0 per descriptor (`InetReadiness`); POLLRDHUP is derived from POLLIN with FIONREAD 0 on a stream. A thread that waits (blocking call, or `poll`/`select`/`epoll` with AF_INET sockets about) sleeps as `WaitKind::Net`; the scheduler polls every live socket once per pass while one waits, sleeps in the host `poll` (at most 8 ms) when idle, and ends the wait when readiness changed or reached what a blocked call waits for |
| AF_INET `fcntl(O_NONBLOCK)` | Changes only the guest flag; the host descriptor stays nonblocking |
| AF_INET `read`, `write`, `readv`, `writev` | As `recv` and `send` without flags (a vectored UDP write is one datagram) |
| Peer closes with unread data | A stream or seqpacket peer sees ECONNRESET once, after the data it already had, then EOF; queued but never accepted connections reset their connector |
| AF_INET socket errors in `poll` | Console 0.14.1: a connected UDP socket whose datagram drew an ICMP port unreachable made the host `recv` fail with ECONNREFUSED, but the host `poll` did not set POLLERR. This is a translation, not a missing feature: `InetReadiness` reads the host SO_ERROR when the host flags the socket readable (datagram) or POLLERR/POLLHUP (stream), keeps it as the pending error that `recv` and SO_ERROR report once, and shows POLLERR while it is pending. A nonblocking connect the host finished is decided in `InetReadiness` too (refusal: POLLIN, POLLOUT, POLLHUP, POLLERR) and stays decided until the next `connect()` returns 0 or the connect error, as Linux keeps SS_CONNECTING |
| AF_INET datagram `FIONREAD` | The host counts every queued byte; the runtime peeks the next datagram and reports its size, as `udp_ioctl` does |
